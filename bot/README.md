# SquirtCar — телеграм-бот

Диалоговая версия калькулятора из `SquirtCar_0.1.2.html`. Вся математика перенесена
в Python один в один: те же формулы аннуитета, амортизации, топлива, экономии времени,
«счастья» и симуляции накоплений на 10 лет. Графики рисует matplotlib с теми же
палитрами, что и canvas в вебе (светлая / тёмная / киберпанк).

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
BOT_TOKEN=<токен от @BotFather> .venv/bin/python -m squirtcar.bot
```

Состояние диалогов складывается в `squirtcar_state.pickle` рядом с местом запуска
(путь меняется переменной `STATE_FILE`).

## Хостинг

Бот работает на long polling: HTTP-порт ему не нужен, нужен постоянно живой процесс
и диск под `squirtcar_state.pickle`. В `Dockerfile` состояние по умолчанию пишется
в `/data`, куда обе платформы монтируют диск.

Важно: токен нельзя опрашивать из двух мест одновременно — Telegram начнёт отдавать
`Conflict` и терять апдейты. Поэтому в конфигах жёстко один инстанс, и на время
деплоя локальную копию надо останавливать.

### Railway

1. New Project → Deploy from GitHub repo → `key-peskov/squirt-car`.
2. В настройках сервиса **Root Directory** = `bot` — иначе Railway не найдёт
   `Dockerfile` и `railway.json` и попробует собрать репозиторий как статику.
3. Variables → `BOT_TOKEN` = токен от @BotFather.
4. Volume → Mount path `/data` (переменная `STATE_FILE` уже указывает туда).
5. Deploy. В логах должно появиться `SquirtCar bot запущен`.

`railway.json` фиксирует сборку из Dockerfile (`builder: DOCKERFILE`), один инстанс
и рестарт при падении. Отдельная версия Python не нужна — она зафиксирована базовым
образом `python:3.12-slim`.

### Render

В репозитории лежит `render.yaml` (blueprint, в корне — Render читает его только
оттуда). New → Blueprint → выбрать репозиторий → Render поднимет worker с диском
на `/data` и спросит `BOT_TOKEN`.

Оговорка: worker на Render платный (минимум starter). Бесплатный план бывает только
у web-сервисов, а они засыпают без входящих запросов — для polling-бота не годится.

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/ruff check ..
```

Тесты покрывают математику (`calc`), разбор полей (`model`), тексты отчёта (`report`),
видимость полей по переключателям (`sections`), HTML-экспорт (`share`) и рендер графиков
(`charts`). Формулы проверяются независимым способом — например, аннуитет сверяется
дисконтированием потока платежей обратно к сумме кредита, а не повтором той же формулы.

Отдельно есть сверка с оригиналом — `tools/verify_against_html.py`, см. «Сверка с
оригиналом» ниже. В CI она не участвует: ей нужен `jsc`, который есть только в macOS.

## Как устроен диалог

Все поля уже заполнены теми же значениями по умолчанию, что и в HTML, поэтому
результат можно смотреть сразу, а править — только то, что важно.

```
/start → выбор сценария → меню
  ├─ 🚗 Текущая машина / 🆕 Новая машина / 🏠 Жизнь и накопления
  │    поля правятся по нажатию: бот спрашивает значение сообщением
  │    переключатели (топливо, амортизация, кредит, оплата, trade-in) — кнопками
  ├─ 📊 Показать результат  → текст + 2–3 графика
  ├─ 🔗 Скачать HTML        → тот же файл, что даёт кнопка «Поделиться» в вебе
  └─ 🎨 Тема / 🔄 Сбросить / ← Другой сценарий
```

Команды: `/start`, `/menu`, `/result`, `/share`, `/theme`, `/reset`, `/help`.

## Модули

| Файл | Что внутри |
|---|---|
| `model.py` | поля формы, значения по умолчанию, переключатели, состояние пользователя |
| `calc.py` | вся математика — построчный порт скрипта из HTML |
| `sections.py` | какие поля показывать при текущих переключателях (show/hide из HTML) |
| `report.py` | текстовый отчёт и инсайты (тексты перенесены дословно) |
| `charts.py` | три графика на matplotlib, палитры из `getColors()` |
| `share.py` | экспорт расчёта в HTML — порт `buildSharedHTML()` |
| `bot.py` | экраны, клавиатуры, хэндлеры |

## Сверка с оригиналом

```bash
.venv/bin/python tools/verify_against_html.py
```

Скрипт выполняет настоящий JS из `SquirtCar_0.1.2.html` в JavaScriptCore (`jsc`,
есть в macOS из коробки) поверх DOM-стаба и сравнивает результат с Python-портом.
На семи наборах входных данных сходятся все значения, которые страница пишет в DOM
(месячные суммы, разбивки, доли дохода, параметры кредита, накопления), все точки
трёх графиков и тексты инсайтов. Запускать после любой правки формул.

## Чего в боте нет

Поиск цен по ссылкам на Авто.ру / Авито / Дром — в HTML это просто внешние ссылки,
в диалоге им нет места. Всё остальное перенесено.
